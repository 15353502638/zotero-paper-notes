# Zotero 图文精读笔记

## 调用与完成标准

工作流：查找 Zotero 文献 → 读取全文和图 → 按选定模板撰写中文精读 → 嵌入原图 → 写回该文献的子笔记 → 核验。支持自然语言和 `$zotero-paper-notes 文章名`。用户已约定“以后只发文章名就做笔记并写回”时，后续标题输入直接执行；未作约定且意图不明的孤立标题，不自行当作写入请求。明确只问概念、翻译、检索或只生成草稿时，按当前请求执行。

写回依据当前用户的请求或已有约定；技能安装本身不代表用户已授权写入。明确请求运行完整流程时无需重复询问“是否写回”“是否配图”。范围限于指定文章的本流程笔记、PDF 和图片，不覆盖其他笔记、原文元数据、全局模板、同步设置或访问权限。

成果是 Zotero 中的图文笔记，单独 HTML 文件只作副本或受阻时交付。默认处理全部主图，数量由论文决定；补充图按解释关键机制的需要选取。不要固定为 STING、五张图、旧条目 key 或旧 PDF 页码。

## 工具与资料路由

- 读取库和全文：优先使用可用的 Zotero 连接工具；安装了 `zotero:Zotero` 时先读其说明。插件版本和 Python 路径从当前环境解析，不写死旧路径。没有该插件时可按 operations 使用 Zotero 本地只读 API。
- 提取和检查图：可用时遵循 `pdf:pdf` 技能；否则使用当前环境的 PDF 提取/渲染工具及图像查看工具。原图提取属于读取，不重画或生成实验图。
- Windows 写回：若无可用的正式笔记写入工具，使用 `computer-use:computer-use` 技能，在 Zotero 内置“工具 → 开发者 → Run JavaScript”执行准备好的本地更新脚本。先读其 guidance、api、confirmations；不得用 shell UI 自动化或直接改数据库来替代。
- 具体 API、图片存储、可靠写回方式见 [references/operations.md](references/operations.md)。文稿质量和模板规则见 [references/note-writing.md](references/note-writing.md)。
- 已验证 Windows + Zotero 9 桌面端个人文库；群组库和其他系统的写回不在附带 helper 的验证范围。没有受支持的写入工具或桌面控制能力时，完成本地文稿并明确尚未写回。
- 模板选择与配置见 [references/templates.md](references/templates.md)。用户可选自己的模板；没有自己的模板时直接使用 [assets/note-template.html](assets/note-template.html)，不要求先配置模板。

## 工作流

### 1. 定位文章和目标笔记

用标题搜索，核对标题、作者、年份、DOI 与附件。唯一匹配时直接继续；多个相近匹配时列出最小必要的候选让用户确认，不能选择搜索结果第一条充数。中文译名/简称可结合已知作者年份定位，最终以库中真实条目为准。

读取目标文章的子条目。按 templates 选择模板，再选择与之相容的空白模板笔记，或更新明确由本流程生成的精读笔记。用户此次指定的模板优先于旧空白实例。已有用户实质性笔记时保留其内容，通常新建独立精读子笔记；只有用户要求编辑时才合并。若无笔记，在该文献下通过 Zotero 新建子笔记并套用选定模板。多个候选无法区分时才询问。

先保存目标笔记完整 HTML 和父条目 key 到当前工作区 `work/`。检查模板栏目、标题层级、颜色及表格等结构；编辑实例，不改变全局模板。

### 2. 读取全文并建立图表映射

读取 PDF 或完整索引文本，检查 indexedPages/totalPages。不能以摘要冒充全文。索引不全时读实际 PDF；本地全文不可用时才寻找合法可访问原文，仍不可得则说明缺哪份文件。

阅读正文、方法、讨论、主图图注及相关补充内容。建立“图号 → PDF 物理页码 → 提取文件 → 对应结果段落”映射，区分印刷页码和 PDF 页码。

优先直接提取 PDF 内完整图像对象，保留原分辨率；若主图由矢量或多个对象组成，渲染整页并按实际边界提取。逐图视觉检查 panel、坐标轴、图例和比例尺，不能假定一个 image object 就是完整主图。不截掉不支持结论的 panel，不用 AI 重绘替代原始数据。

### 3. 按模板撰写并嵌入原图

按选定模板保留标题、栏目顺序、颜色和表格，填入中文内容。自定义模板无需采用内置模板的栏目或占位符名称。内置默认栏目及字段说明见 templates；不把默认栏目强行添加进用户模板。

无论模板怎样命名栏目，研究背景、科学问题和技术路线都必须构成一条可追溯的论证链，不能分别写成概括、问题清单和技术名词清单：

1. **研究背景写清课题来源。** 从领域目标与已有认识写起，逐步收窄到本文的具体知识缺口；说明该缺口为何重要、研究者为什么选择这个对象，以及原文明确提供了哪些前期基础。前期基础可以是既往研究、作者团队的先前发现、本文开篇的预实验或选择该模型/靶点的直接依据。原文没有明确前期基础时写“原文未给出直接前期数据”，不可替作者补造动机。
2. **科学问题由背景递进推出。** 用编号问题呈现，后一问必须建立在前一问可能得到的答案上。常见次序是“现象/分布是否存在 → 具体对象或连接是什么 → 是否具有机制或因果作用 → 作用发生在哪个环节及边界是什么”，但应按论文实际逻辑调整。每问都要指出待判定的未知量，不能把技术名称或结果改写成问句。
3. **技术路线写成检验链。** 按研究决策顺序说明“对应科学问题/假设 → 为什么选该模型或方法 → 操作与关键对照 → 核心读出 → 该结果怎样决定或支撑下一步”。强调实验之间的承接关系；试剂、仪器和操作细节只在影响推断时保留。

写完后做反向检查：每个科学问题都能在研究背景中找到来源；技术路线的每一步都能标到某个问题；结果段能回答对应问题。任一项无法对应时，重新组织这三部分。

在模板指定的图文/结果区域按各主图排列：图题 → 完整原图及来源链接 → 实验设计 → 主要结果 → 本图支持的结论及限制。模板未设插图区时放入最相关的正文栏目；补齐关键对照和样本单位。结果段沿用前述问题编号或明确指出“回答问题几”，让背景、问题、路线和证据闭环。

将作者结论、作者推测、阅读者评价分开标注。“我的评价”注明 AI 辅助拟写，供用户修改。影响因子缺失时注明待核实；PubMed Central 不是影响因子。不要套用此前论文的机制或数值。

图片必须成为 Zotero 笔记的嵌入式图片附件，使用真实 `data-attachment-key` 引用，不能只插磁盘路径或远程链接。每图加原文图号与 `zotero://open-pdf/...?...page=...` 来源跳转。窄侧栏可缩放，但保留原始图片字节。

### 4. 写回和核验

先在工作区形成可审查的最终 HTML、图片和更新脚本。附带 helper 可生成有旧内容检查的更新任务，详见 operations。执行前再次读取目标笔记；用户已改动时重新合并，不覆盖。

脚本或 UI 返回不确定结果时，先通过只读 API 核实当前笔记和附件。禁止盲目重跑造成重复图片或笔记。不能确定部分写入范围时停在现状，说明已完成和未完成部分。

核验父条目、最终 HTML 文本、图像数量/顺序、附件存在和内容、来源页码，确认应保留的原有内容仍在。能操作窗口时查看实际排版；用户操作中断时先重新观察，必要时请用户短暂停用鼠标键盘，避免反复争抢前台。

完成后简短报告文章名、主图数量及确有的缺失。不要让用户阅读调试日志或重复确认已授权的写回。若只能生成本地副本，明确“尚未写回”。
